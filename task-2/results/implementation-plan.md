# Task 2. Верхнеуровневый план реализации и конфигурации

## 1. Уточнение контракта выгрузки

- Согласовать структуру CSV/XLSX: набор колонок, порядок, кодировку, разделитель, формат дат/чисел.
- Определить правила формирования имени файла: `price-list_<client_id>_<yyyyMMdd>.csv`.
- Определить полноту данных: только активные товары/клиенты, валюта, timezone, поведение при отсутствии индивидуальной цены.

## 2. SQL и доступ к данным

- Подготовить параметризованный SQL-запрос с join:
  - `client_prices` как источник индивидуальных цен;
  - `products` для SKU, названия, единиц измерения;
  - `categories` для иерархии/названия категории;
  - `clients` для реквизитов клиента и признака активности.
- Добавить индексы на `client_prices(client_id, product_id)` и связанные внешние ключи, если они отсутствуют.
- Использовать server-side cursor/streaming, чтобы не загружать весь результат в память.

## 3. Реализация exporter-приложения

- Создать небольшое приложение `price-list-exporter` на языке, принятом в команде.
- Реализовать шаги:
  1. загрузка конфигурации;
  2. проверка доступности БД и объектного хранилища;
  3. выполнение SQL;
  4. потоковая запись CSV/XLSX;
  5. контроль количества строк;
  6. загрузка файла в хранилище;
  7. публикация результата в лог и метрики.
- Сделать запуск идемпотентным: временный файл + атомарная публикация финального объекта; при повторном запуске перезаписывать объект той же даты.
- Добавить ограничение времени выполнения и понятные коды ошибок.

## 4. Контейнеризация

- Собрать минимальный Docker-образ.
- Запускать процесс от non-root пользователя.
- Вынести параметры в переменные окружения.
- Проверить образ локально на тестовой БД.
- Публиковать образ в registry с immutable tag.

## 5. Kubernetes-конфигурация

- Создать namespace, service account, ConfigMap и Secret.
- Настроить CronJob:
  - `schedule: "0 6 * * *"`;
  - `timeZone` целевого региона;
  - `concurrencyPolicy: Forbid`;
  - `backoffLimit: 2–3`;
  - `activeDeadlineSeconds` для защиты от зависаний;
  - `successfulJobsHistoryLimit` и `failedJobsHistoryLimit`;
  - requests/limits CPU и memory.
- Настроить минимальные RBAC-права, если приложению нужен доступ к Kubernetes API. Для простого экспорта доступ к API не нужен.

## 6. Хранение и доставка результата

- Выбрать целевое хранилище: S3/GCS/Azure Blob или внутренний file-service.
- Настроить bucket/container, lifecycle policy и retention.
- Сформировать права доступа по принципу минимума: exporter может только писать в заданный prefix.
- Определить канал доставки клиенту: портал, email со ссылкой, SFTP или API.

## 7. Наблюдаемость

- Структурированные JSON-логи в stdout.
- Метрики: длительность job, строки, файлы, ошибки БД, ошибки хранилища, retry count.
- Alert при failed Job, превышении длительности, отсутствии успешного запуска за сутки или нулевом количестве строк.
- Dashboard с историей запусков и объёмами выгрузки.

## 8. Тестирование

- Unit-тесты маппинга строк в CSV/XLSX.
- Интеграционный тест с тестовой PostgreSQL.
- Тест повторного запуска и идемпотентности.
- Тест ошибок: недоступная БД, недоступное хранилище, пустой результат.
- Нагрузочный smoke-тest на объёме 20–30 тыс. строк с запасом.

## 9. Внедрение

- Развернуть в staging.
- Сравнить результат с эталонной выгрузкой.
- Включить CronJob в production сначала в режиме записи в тестовый prefix.
- После приемки переключить delivery-канал и включить alerting.
